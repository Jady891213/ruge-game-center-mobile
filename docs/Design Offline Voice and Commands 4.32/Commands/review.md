# 口令小冒险：离线口令修正与证据（4.32）

## 实施范围

继续使用原包内 sherpa-onnx 模型、tokens、JNI 与 JAR，不引入云识别或新增权限。15 个动作共 92 个实际短语，词表、网页映射、可滚动口令卡来自同一 `commands.json`；每个动作至少 6 种说法。`take` 有 8 种。全部是有限词表识别，不是自由语义理解。

## 已修正的具体问题

1. 原词表已经有“前进”“往前”，Mac CPU 对照也能够识别，不能把用户的原问题归因为漏注册。扩大常用词、轻声与变调 token 后，旧词表会把“向左转”截为向左的样本得到改善。重叠 token 的 trailing blanks 按官方说明由 4 改 8；不是无限等待，也没有把每个词后重启麦克风。
2. 原生同一解码批次只保留最后口令、网页忙时只覆盖一条口令，都会丢连续动作。现在原生保留 16 个事件，网页按 FIFO 保留 6 个；均丢弃超过 1200 ms 的命令，重复“前进”保留独立序号。停止、暂停、重开、离开清队列；队列首条碰墙也继续处理后续有效动作。
3. `GameAudio.start` 的主线程排队增加请求 generation 校验，页面停止或离开后旧请求不能迟到重新开麦；正常连续关继续复用同一采集。真实 Java 源码测试覆盖取消与复用。
4. 已听到但受墙或任务阻挡时保留口令名，例如“前进 · 换个方向”，区分识别与不可移动。前进/后退仍相对角色面朝方向，后退不转身，不穿墙。
5. 用户明确点麦克风“重新听”才 stop→start，保留角色与本局进度；每词、每次下一关不自动重启。真实页面处理器回归确认 stop/start 各调用一次、角色快照不变、普通下一关不多开采集。

## 真实模型验证

本目录报告来自实际包内 ONNX 模型和 token，在隔离的官方 macOS arm64 sherpa-onnx 1.13.8 CPU 运行时执行，逐块输入 16k PCM。没有将 VM 的识别夹具作为真实识别率，也没有安装全局 Python 包或改 APK 原库。轮子校验见 `cpu-runtime.json`。Mac 声音为 Tingting 150 wpm；自然样本为已授权 MiniMax 合成标准音。合成声不能代表五六岁儿童的音域、口音、距离或噪声识别率。

| 对照 | 结果 |
|---|---|
| 原词表首轮：90 正例 + 20 语音负例 + 3 噪声 | 78/113 |
| 最终 92 条 Mac 正例 | 88/92；15 个动作均至少 5 条实际命中 |
| 最终 20 条语音负例 | 20/20 拒绝 |
| 最终 3 条噪声 | 2/3；特定彩噪声误触一次 stop |
| 同一批 12 条 MiniMax 自然音，旧 / 新词表 | 6/12 → 12/12 |
| 同一个 stream 连续 19 条自然音，旧 / 新 | 12/19 → 18/19；新版本末条前进仍漏 |

上述不同矩阵分母不能混为一个总准确率。第一轮 113 条含 90 正例，最终 115 条含 92 正例。连续矩阵的固定否定短语命中 `__ignore__` 后不派发动作，按正确拒绝计算。

### 真机边界

父任务使用 MIX 4 扬声器播放同一批合成音、真实麦克风/Android JNI 识别，未保存人声或房间录音。真机结果在本目录上级的 `device-commands-*.json`。这会受到手机自身回声处理、音量和会话状态影响，不可直接当成人声识别率：

- 旧版同一采集会话“前进 / 往前 / 向前”为 1/3；旧版每句新采集为 3/3。
- 新版同一采集为 2/3（向前漏）；新版每句新采集 12 条中“往前 / 向前 / 向左”漏听。不能声称新版每条短句真机都提高。
- 检查 12 条 fresh 的最后 canonical 仍不足：“向左转”出现 serial +2，角色也移动，并非预期的原地转身；“拿东西”出现 serial +2，可能重复执行。此处已向父任务报告，最终验收应同时看事件数、坐标与朝向，不能只看 last command。
- 需要真实儿童轻声/连续说话试玩，才能进一步判断短句漏听。当前未为内部扬声器回录样本任意降低阈值。

### 已拒绝的实验

曾用实际 `VoicePitch.java` 对同一批 PCM 逐帧作最近有声门控。虽然消除了彩噪声误触，却额外漏掉向下、左转一下、右转一下、蹦一下、放下 5 条有效命令，因此没有发布这个门控。`final-gated-cpu-results.json` 只是被否决的对照，不代表交付算法。固定 6 条否定短语是关键词抑制，不代表理解所有“不要……”表达。

## 回归与复跑

- `tests/voice-command-catalog.test.mjs`：单源生成一致性、所有 token、15 动作/92 短语、重复命令 FIFO、失效丢弃、墙后继续消费、真实 Java 生命周期和显式重新听。
- `tests/quest-polish.test.mjs`：保持原同一角色实体/动画路径测试，将已过时的“只覆盖一条”断言改为要求的 FIFO 两步实际执行。
- 本轮命令与旧动作相关 26 项通过；最后重新听变更后 catalog + quest-polish 12 项通过。完整项目回归由父任务记录。
- `python3 scripts/generate-voice-commands.py --check` 检查实际生成文件，不访问云。
- `scripts/check-voice-commands-cpu.py` 是复跑工具，需要预备已校验的隔离 runtime，使用 Mac say / ffmpeg 和真实模型，不访问云、不采麦。新工具已做语法验证；本轮数值来自已实际执行的隔离实验脚本与 JSON，不把工具存在视为又跑过一轮。

```sh
python3 scripts/check-voice-commands-cpu.py \
  --runtime-dir "TMP to delete-commands-432/runtime" \
  --output "TMP to delete-commands-432/recheck.json" \
  --standard-audio
```

`Standard Audio/` 为 12 条可复核合成标准音，`sources.json` 保存文本、预期动作与 SHA，不含密钥、签名 URL 或任何儿童录音。`TMP to delete-commands-432/` 内 runtime / Mac 中间音 / 实验脚本是可删除临时产物；真机验收尚使用时先保留。
