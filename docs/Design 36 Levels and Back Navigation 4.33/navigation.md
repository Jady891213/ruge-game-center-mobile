# 4.33：逐层返回

## 行为

Android 侧滑/系统返回先交给当前页面；顶部返回箭头共用同一协议。到游戏自己的入口后，再返回游戏中心；游戏中心再次返回才退出应用。明确标为“回游戏中心”的按钮仍可直接退出游戏。

## 暂停与数据

- 返回关闭暂停层时，底层保留 paused，不偷偷恢复重力、计时、洗牌或麦克风。
- 页面中央显示唯一的大号“▶ 继续”。透明点击遮罩阻止误触背景控件；按钮居中，不盖底部输入键盘。再次返回去选关；明确点继续才调用本游戏原有 resume（钢珠仍走原水平检查）。
- 切后台隐藏继续入口，回前台恢复同一入口；不会删掉唯一恢复路径。真正离开页面清理按钮和遮罩。选关/重置取消后仍有原暂停入口。
- 返回调用各游戏现有 menu/save/cancel 等方法；保留草稿、已找到的字、星数和其他游戏存档。口令菜单取消请求、停麦并清动作队列，迟到识别不再改变角色。
- 飞机与英语在游戏内部返回保持横屏；真正离开游戏才恢复竖屏。

## 实现边界

- `shared/back-navigation.js` 是页面返回协调入口，`onRugeBack` 由每款游戏的真实闭包注册。没有复制游戏规则，亦不使用 `history.back/go/pushState` 推测层级。
- 字库由打字进入时只带固定 `?from=typing`，用于选择合法的打字父页；直接从合集进入不添加额外父级。原字库 hash 继续使用 replaceState，不堆浏览历史。
- 原生 `onBackPressed` 等待当前页面消费结果；pending 防重入，短时间重复事件去抖。页面换址或 Activity 暂停使 generation 失效。
- JS 本体执行前通过 `RugeNav.backRequestActive(generation)` 校验请求仍有效；callback 也核对 generation、前台及当前 URL。这样暂停再恢复到同 URL 的旧请求也不能误退。
- 1200ms 超时仅解除 pending 以允许重试，不触发“超时回首页”。页面异常同样不强行退出。仅缺少页面协议才由原生兜底回合集。
- 使用既有 Android WebView/Activity API，无新依赖/权限。API线程与异步结果核对参考 [Android WebView 官方说明](https://developer.android.com/reference/android/webkit/WebView#evaluateJavascript(java.lang.String,%20android.webkit.ValueCallback%3Cjava.lang.String%3E))；Context7 检索后以官方 API 页为准。

## 自动验证

另跑动作、学习、密码箱、口令、飞机及水管等既有相关回归：96/96 通过。

`node --test tests/back-navigation.test.mjs tests/back-navigation-native.test.mjs`：**48/48 通过**，原始输出见 `navigation-tests.txt`。

- 真实打包页面 VM：所有游戏层级、重置不清草稿、字库上下文、暂停不自动恢复、唯一继续入口、前后台继续入口、选关/重置关闭保留暂停、口令清理、横屏保持。
- 真实 `MainActivity.onBackPressed` 方法提取后由 Java 编译执行：消费/兜底、重入、重复事件、换页、超时无导航、迟到 callback、暂停恢复同 URL、首页退出。生成的测试目录在 finally 删除。
- 原飞机方向测试已改为验证连续层级：第一次关闭暂停层仍横屏，第二次回飞行入口仍横屏，真正离开才竖屏；保留原方向契约，并未删去断言。
- VM 不绘制真实像素，也不能代替 Android 侧滑、IME、实际录音或设备生命周期验收；真机记录由主任务统一交付。
