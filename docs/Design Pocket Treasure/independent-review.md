# 口袋探宝独立审查与浏览器验收

## 已修复

1. **双人交接后台死锁**：交接弹层期间切后台会同时留下暂停层和交接层，准备按钮因暂停失效，继续又被交接状态拒绝。现在暂停只展示暂停层，明确继续后恢复交接，再按准备开始。
2. **完成草稿无法继续**：已通关存档从菜单继续时，finished 状态没有显示结算，无法点击下一关。现在恢复完成草稿直接显示结算及下一关，不重复播放获胜反馈。
3. **无传感器仍计时且备用提示丢失**：缺失/过期输入时暂停本局计时和停稳进度，显示“试试手指”与大按钮。探宝此前该文案会在同帧 refresh 被找宝箱覆盖，现用明确的画布遮罩。
4. **双人体感起点不一致**：每名玩家按准备后先把手机转正，才开始计时，避免预对着密码直接完成；手指从相同0度开始，保持同一密码与输入方式。
5. **暂停后旧拖动恢复**：暂停清除 dragging 标志，继续后的 pointermove 不会恢复之前的地图拖动。
6. **显示同分却判输赢**：原先按隐藏精度比较，可能两人均显示1.5秒却判某人获胜。现按展示的0.1秒精度判平局。
7. **错误提示瞬间消失**：“再找找”保留700ms，不再被下一动画帧覆盖。
8. **视觉小问题**：钥匙/宝箱/星星使用清晰 SVG，转动按钮使用左右弧形 SVG；菜单标题保留右侧空位居中；窄墙圆角不超出半边长；小屏方向按钮至少44px。
9. **获胜震动被取消**：原流程先播放 win、再清输入取消震动、随后第二次 win 被共享去重拦截。现统一清理探测震动后只触发一次 win，增加反馈事件顺序回归。

双人重置仍重新开始整场比赛，确认文案明确为“重新比赛？”。比赛不写入单人星星、最佳成绩或草稿。单机轮流模式仍允许另一个玩家观察屏幕；它是家庭同屏挑战，没有实现防旁观或严肃竞赛防作弊。

## 验证

- `node --test tests/pocket-radar.test.mjs`：15项通过，见 `tests-independent.txt`。
- 原有18保险箱实际角度/停稳解锁测试、18探宝地图全部目标 BFS +真实移动/碰撞规则可达测试保持通过，未改 core.js 规则。
- 独立桌面 Chrome 真实鼠标操作：探宝第一关按住地图移动至目标并挖出；第13关通过正常 start API 进入，随后实际按住鼠标沿墙外路线移动并依次挖出钥匙、星星和宝箱。保险箱从第1关开始，通过实际鼠标点旋钮、真实等待停稳、点击下一关完成全部18关，没有直接置 finished 或 index。
- 双人真实两轮：每名玩家交接期间触发 `ruge:pause`，实际点击继续/准备，再实际点旋钮并停稳解锁。比较比赛前后的单人完整 JSON，完全一致。
- 320×568 主页面无横纵溢出，画布292×216，底部操作区止于556px；392×872 另检查正常开锁与双人结果页。截图及测量见同目录 PNG、`browser-review.txt`。
- 浏览器实际切换到“手机”输入后显示无传感器备用入口，等待500ms前后 elapsed完全相同，点“用手指”可恢复。此项没有注入传感器桩。
- 浏览器测试使用独立实例和本机127.0.0.1 HTTP，均在 finally 关闭。仅 favicon.ico 404，没有游戏脚本错误。临时浏览器资料放 `TMP to delete-pocket-browser` 并于验收后清理。

## 验证边界

浏览器使用手指/鼠标备用输入，没有验收 MIX 4 的重力方向、实际震动强度与波形。浏览器无传感器时的备用入口可测，不能据此声称真机体感与触觉已经验收。18探宝关全可达来自核心移动规则搜索；浏览器实玩覆盖代表关卡。保险箱18关均在真实浏览器画布操作通过。
