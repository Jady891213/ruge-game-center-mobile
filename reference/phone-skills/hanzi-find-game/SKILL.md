# 汉字找字小游戏（抖音小游戏）

> 这是一个**具体游戏的操作手册 + 进度存档**。
> 每次玩完**必须更新 §6 进度**，否则下次会话接不上。

## 0. 两条红线（先看这个）

1. **绝不点「跳关」和「提示」** —— 这两个按钮带**摄像机小图标**，意味着**要看广告**。
   会消耗用户的账号和时间。**一次都不许点。**
2. **卡住就问用户，不要反复盲试。**
   实测：密集笔画区里盲试的命中率会掉到 0，一次尝试约 5 次工具调用 / 15 秒。
   **连续 2 次失败就停下来问**，把当前选区、已试过的组合、你想要的答案集说清楚。
   （用户明确说过：不通就问他，"不然要看广告很麻烦"。）

## 1. 这是什么游戏

屏幕上一个大字（书法体），要从它的**笔画**里拆出 **N 个常用字**。
顶部 N 个米字格空格，每找对一个填一个（带拼音）。

**首次遇到的那一关**：第 102 关，大字「**瑰**」（王 + 鬼），目标 **14 个字**。

## 3. 机制（已实测确认）

| 操作 | 效果 |
|---|---|
| **点某根笔画** | 该笔画**变深色** = 选中；再点一次取消 |
| **点「全选」** | 全部笔画选中 |
| **点「提交」** | 校验当前选中组合；**通过 → 顶部空格填入该字 + 拼音** |
| **第三个按钮** | **循环切换**：选区为空时是「全选」，有选区时是「重置」 |
| **「重置」** | 清空选区 |

### 3.1 失败判据（最有用的一条）

> **提交后截图逐字节不变 = 这个字不通过。**

实测可靠。可以这样判：

```sh
md5sum 提交前.png 提交后.png      # 一样 = 被拒
```

被拒后**选区会保留**，方便你调整；换思路前记得先点「重置」。

### 3.2 高效套路

- **要的字是图形的一大部分** → 点「全选」，再**逐个取消**不要的笔画
  （「鬼」就是这么抠出来的）
- **要的字只有几笔** → 直接点那几笔
- **判定很宽松**：实测一道**斜撇**被当成横用，「三」照样通过 —— 别被"必须水平"限制住
- **可以一次消息里连发多个 tap**（顺序执行），比一个个来省一半往返

## 5. 用坐标找笔画的辅助手段

笔画颜色 `rgb(189,155,110)`，卡片底 `rgb(249,250,238)`。
判据：`(r-b) > 35 and 140 < r < 235`。

把截图解码成 PNG，再对目标区域做**行/列投影**（命中数高的行 = 横笔画，列 = 竖笔画）。

**工具已就绪**：本技能目录的 `analyze.py`

```sh
python3 ~/.dsh/skills/hanzi-find-game/analyze.py <截图.png> <x0> <y0> <x1> <y1>
```

**✅ 已交叉验证**（在左边「王」区域跑，输出与手点结果完全吻合）：

| 笔画 | 手点坐标 | 脚本算出 |
|---|---|---|
| 王·上横 | y 1140 | y 1137 |
| 王·中横 | y 1385 | y 1382 |
| 王·下斜笔 | y 1650 | y 1646 |
| 王·竖 | x 262 | x 258 |

所以**坐标表是可信的**，直接用。

> 教训：**这个手段在密集区不好使**（「鬼」的上半方框几十笔重叠，投影是一片糊）。
> 稀疏区（比如左边的「王」）很准。**别在密集区硬上，直接问用户更快。**

| 白 | bái | 用户自己找到 |
| 土 | tǔ | 用户自己找到 |
| **珀** | pò | 用户自己找到 —— **王 + 白（跨左右部件！）** |

**剩下的 2 个（格子 13、14）候选**（按可能性排序）：

1. **田** —— 甶 里「日」再加中间那根**竖**。日已找到，田是最自然的下一步。
2. **儿** —— 鬼 底部的两笔（撇 + 竖弯钩）。屏幕坐标约 `(670,1600)` 和 `(860,1620)`。
3. 备选：厶 / 工 / 由 / 甲 / 旺(日+王) / 皇(白+王) / 玉(王+丶)

**重要结构认知**（这次才搞明白）：

> 笔画按**书写顺序**拆分，所以一个字不一定是"几笔就是几画"。
> 例：**「口」在这里是 3 笔**（竖 + 横折 + 横），因为**横折一笔就含了上边和右边**。
> 选之前先想"书写时这几笔是连着的吗"。

**已试过且被拒的**（别重复）：
- 王·上横 + 竖（想拼「十」）→ 拒 ⇒ **「十」不在答案里**
- 王·上横 + 下斜笔 + 竖 → 拒
- 鬼·上半方框外四笔（按 4 笔拼「口」）→ 拒（正确的是 3 笔）

## 7. 给"我们自己的游戏"的设计参考

这个游戏有几处值得抄：

- **选中态高亮** —— 用户随时知道自己点了什么
- **按钮上下文复用** —— 有选区时「全选」变「重置」，省一个按钮位
- **判定宽松** —— 斜笔算横，对孩子友好，减少挫败

反面教材（**对 AI 和读屏都不友好**）：

- 整块 canvas，**控件树里一个内部节点都没有** → 只能靠像素猜坐标
- 点错**没有任何反馈** → 无法通过试探学习规则
- 关键功能（跳关/提示）**藏在广告后面**

> **结论**：想让界面能被自动化/AI 操作，要么用 DOM（有语义节点），
> 要么**主动暴露状态接口**（像我们游戏里那个 `?debug=1` 调试条）。
> canvas 是刻意的不透明 —— 别在自己的产品里这么干。
