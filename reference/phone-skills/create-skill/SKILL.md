# 写一个 skill：从需求到可被加载

## 0. 心智模型（先搞对，再动手）

skill = **一段按需加载的指令文本**。它不像系统提示那样常驻，而是分两层：

| 层 | 内容 | 何时进上下文 |
|---|---|---|
| **catalog（目录）** | 所有 skill 的 `name` + `description`，一行一条 | 每个会话开场就注入系统提示 |
| **正文** | SKILL.md 的 markdown 正文 | 只有模型调 `skill` 工具、或用户 `/名字` 时才加载 |

**由此推出两条铁律**：

1. **`description` 决定这个 skill 会不会被用上。** 正文写得再好，description 没写准触发条件 = 永远躺在目录里没人点。
2. **正文可以写长。** 它只在被加载时才吃上下文，200~400 行完全没问题；不用为了"省 token"把正文砍成谜语。

## 1. 三分钟最小可用版

```bash
# 用户级根（跨项目通用，最常用）
mkdir -p "$DSH_HOME/skills/my-skill"      # $DSH_HOME 通常是 ~/.dsh
```

```markdown
<!-- $DSH_HOME/skills/my-skill/SKILL.md -->
---
name: my-skill
description: 一句话说清「什么时候该用我」，而不是「我是什么」。
---
# 正文标题

## 固定顺序
1. 第一步——**可直接复制的命令或代码**。
2. 第二步。
3. 失败了怎么办。

## 纪律
- 明确的禁止项。
```

**目录名建议与 `name` 一致**（加载器以 frontmatter 的 `name` 为准，不一致不会报错，但维护起来很乱）。

## 2. 放哪里：发现路径与优先级

加载器会扫描这些根，**目录包**（`<name>/SKILL.md`）和**单文件**（`<name>.md`）都认：

| 放置位置 | 路径 | 适用 | rank |
|---|---|---|---|
| **用户级**（推荐默认） | `$DSH_HOME/skills/` | 跨项目通用、跟人走 | 400 |
| 用户级（agents 约定） | `$DSH_AGENTS_HOME/skills/`（默认 `~/.agents/skills/`） | 想跟别的 agent 工具共用时 | 500 |
| **项目级** | `<项目根>/.dsh/skills/` | 只对该项目生效，**可随 git 提交给全组** | 100 |
| 项目级（agents 约定） | `<项目根>/.agents/skills/` | 同上 | 200 |
| 自定义根 | 由配置的 `customSkillDirs` 指定 | 装在别处 | 300 |
| 插件包内 | `<插件包>/skills/<name>/SKILL.md` | 打包分发给别人 | 600 |

- **项目根** = 从当前工作目录往上找，**最近的含 `.git` 的目录**；找不到就是 cwd。
- **优先级**：同一层内 **rank 小的赢**（项目 < 运行时 < 自定义 < 用户 < 打包）；跨层则「离当前会话最近的层直接赢」。
- 实践结论：**同名时项目级会盖掉用户级**——这是有意的，让项目能覆盖通用规范。
- `.system` 子目录被跳过，别往那放。

## 3. frontmatter：准确字段清单

首行**必须**是 `---`，然后 YAML，再一行 `---` 收尾。

| 字段 | 必填 | 规则 |
|---|---|---|
| `name` | ✅ | 必须匹配 `^[a-z0-9]+(?:-[a-z0-9]+)*$`：**小写字母/数字，单连字符分隔**。不能有大写、下划线、空格、点、首尾连字符、连续连字符 |
| `description` | ✅ | 模型唯一的判断依据。catalog 里会被**压成一行**（连续空白折叠成一个空格），**超过 500 字符截断并加 `...`** |
| `whenToUse` | ❌ | 会被解析保留，但**不进 catalog** —— 别指望它起匹配作用 |
| `disable-model-invocation` | ❌ | `true` = 模型不能自动加载，只能用户 `/名字` 手动调 |
| `user-invocable` | ❌ | `false` = 禁止用户 `/名字` 直接调 |
| `metadata` | ❌ | 任意对象，原样透传（给工具链用的） |

**布尔值**接受 `true/false`、`1/0`、`yes/no`、`on/off`（大小写不敏感）。

⚠️ **历史字段名会被硬拒收**（整个文件被忽略并报错）：`disableModelInvocation`、`modelInvocable`、`userInvocable`。只能用小写连字符版。

⚠️ 缺 `name` 或 `description`、首行不是裸 `---`（有 BOM、空行、前后空格都会翻车）、YAML 语法错 → **整个 skill 被静默忽略**，只在日志里留一条 warn。

## 4. `description` 怎么写（决定成败）

写**触发条件**：用户会在什么话里需要它。

| | 例子 |
|---|---|
| ❌ 自述型 | `这是一个用于处理 Excel 的工具。` |
| ❌ 空泛型 | `帮助用户完成数据处理任务。` |
| ✅ 触发型 | `读取/生成/修改 Excel（.xlsx/.xls）与 CSV：多表合并、透视、公式、图表、格式保留。用户提到 Excel、表格、xlsx、csv、合并工作簿、导出报表时用本技能。` |

要点：
- **堆同义词和用户原话**（中英文都要），因为匹配靠的是语义相似度，不是关键词精确命中。
- **点名动作**（读取/生成/修改/校验）和**对象**（Excel/表格/csv）。
- **写清边界**：「不适用什么」也值得写，能减少误触发。
- 控制在 500 字符内（超了会被截断，截断处往往正好丢掉触发词）。
- 别为了命中率塞无关热词——**误触发比不触发更烦人**，会污染无关任务的上下文。

## 5. 正文怎么写

**给顺序，不给概念。**

- 用编号步骤 + 可直接复制的命令/代码块。不要写「你应该考虑先做 A 再做 B」。
- 明确的**禁止项**和**失败分支**（「如果 X 失败，不要去做 Y，那条路不存在，只会浪费轮次」）。
- 用**表格/清单**压缩信息密度；长表格比长段落好读。
- 正文只在加载时才进上下文，**可以而且应该写详细**。
- 别复述模型已经知道的通用常识，只写**这里特有的、会踩坑的**东西。
- 涉及外部资源（脚本、模板）时，用**相对路径**引用；加载时会告诉模型 skill 的 base directory。

**从一次实际经历提炼 skill 的最快路径**：

1. 回看这次任务里**真正卡住/做错/返工**的地方 —— 那就是 skill 的价值所在（能被教科书查到的不用写）。
2. 每条坑写成「**现象 → 原因 → 修法**」三件套。
3. 把可复用的代码/模板**原样贴进去**，并且**亲自跑一遍验证它能用**（别贴没验证过的模板）。
4. 补齐「开工顺序」和「交付前检查清单」。

## 6. 热加载：写完就能用，不用重启

加载器带 watcher（默认开启），会监听：

- 根目录下**新增/删除子目录**（新 skill）
- 根目录下的 **`<name>.md`**
- **`<name>/SKILL.md`** 的新增/修改

所以：**保存文件 → 立刻生效**，会话的系统提示里的 `<available_skills>` 会**实时刷新**（会看到一条"目录已变更"的提醒）。

## 7. 三步验证（必须做，别假设）

```
① 文件与 frontmatter
   确认路径对、首行是 --- 、name 合规、description 齐全

② 用 skill 工具按名字加载
   skill { name: "my-skill" }
   → 返回 <skill_content>，含 <skill_resources>（base directory）+ <skill_instructions>（正文）
   → 报 "is unknown or no longer available" = 没被发现或名字不对

③ 反向确认：把正文里最容易错的一条拿去实际执行一遍
```

**排错表**：

| 症状 | 原因 |
|---|---|
| 加载报 unknown | `name` 不合规（大写/下划线/连字符位置错）；文件不在被扫描的根里；放进了 `.system` |
| 文件夹里看不到它 | 首行不是裸 `---`（BOM / 前置空行 / 缩进）；缺 `name` 或 `description`；YAML 语法错 |
| 一保存就报错 | 用了老字段名 `disableModelInvocation` / `modelInvocable` / `userInvocable` |
| 名字对但加载的是别的 | 同名 skill 存在多处，优先级更高的根赢了（见 §2） |
| description 显示不全 | 超 500 字符被截断 |

被忽略的文件会在 DSH 日志里留一条 `skill file <path> ignored: <原因>`，这是排错第一现场。

## 8. 用户怎么调用（记得告诉用户）

| 方式 | 怎么做 |
|---|---|
| **自动** | 说相关的话，模型看到目录里 description 命中，自己加载 |
| **手动** | 在输入框打 **`/skill-name`** —— 必须**独立成词**（前面是行首或空白，后面是空白或行尾） |

`/名字` 的识别是白名单式正则，所以 `/usr/bin`、`5/8` 这种**不会被误判**。手动调用会跳过"模型自己判断"，直接把正文注入。

## 9. 反模式

- ❌ **description 写成自述**（"这是一个…的工具"）→ 命中率极低。
- ❌ **正文写成概念导论** → 加载了也不知道该干什么。
- ❌ **把通用常识抄一遍** → 稀释注意力，真正特有的坑被淹没。
- ❌ **贴没验证过的模板代码** → 用户照着跑报错，比不写还糟。
- ❌ **一个 skill 塞三个不相关的领域** → description 没法写准，触发一片混乱。宁可拆成三个。
- ❌ **把密钥/token 写进正文** → 正文会被注入上下文和会话记录。
- ❌ **靠 `whenToUse` 做匹配** → 它不进 catalog，不参与判断。
- ❌ **写完不验证** → frontmatter 一个字符写错，skill 就静默消失了。

## 10. 交付前检查清单

- [ ] `name` 合规（全小写、单连字符）且与目录名一致
- [ ] 首行是裸 `---`，YAML 能解析，无 BOM/前置空行
- [ ] `description` 写了**触发条件 + 同义词 + 边界**，≤500 字符
- [ ] 没用到被拒收的老字段名
- [ ] 路径在 §2 的某个根里，且不在 `.system` 下
- [ ] 正文有**可复制的命令/代码**和**失败分支**
- [ ] `skill { name }` 能成功加载并返回正文
- [ ] 正文里的模板代码**亲自跑通过**
- [ ] 告诉用户「你怎么手动调用它」（`/名字`）
